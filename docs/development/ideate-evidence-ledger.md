## Bounded evaluation fixtures

Use a fixed, nonprivate corpus and the same model/settings when comparing prompt revisions. These are evaluation inputs, not fabricated live results or guarantees.

| Fixture             | Minimum acceptable behavior                                                                                              | Main regression to detect                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| Sparse announcement | Honest concise announcement; request missing facts before a tutorial                                                     | Invented setup, metrics, outcomes, or forced lesson                      |
| Supported workflow  | Supplied steps, prerequisites, and limitation form a reusable sequence                                                   | Generic launch copy or unsupported commands                              |
| Decision/trade-off  | State the choice, cost, and condition that could change it                                                               | Empty “thoughts?” question or false certainty                            |
| Joke                | Preserve earned punchline and factual boundary                                                                           | Mandatory utility essay, CTA, or repeated joke mechanism                 |
| Video requirement   | Supported video surface gets first shot, progression, proof/payoff, and assets; missing media becomes an explicit upload | Caption presented as a video or invented footage/title/thumbnail support |
| Community           | Complete contribution, transparent context, genuine question only when useful                                            | Hashtag quota, mass cross-posting, or assumed local permission           |

Assess source/voice fidelity, concrete usefulness or earned humor, honest payoff, medium feasibility, and editing burden. Record hard failures and win/tie/loss judgments as offline evaluation data only; do not claim live engagement outcomes without an actual documented evaluation.
